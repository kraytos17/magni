# AFL++ Fuzzing Setup

Coverage-guided fuzzing for the **SQL parser** using [AFL++](https://github.com/AFLplusplus/AFLplusplus)
and Odin's AddressSanitizer. Target: `parser.parse` (`src/parser/parser.odin`) —
a deterministic, pure, error-returning function over arbitrary bytes.

## Status

- **Phase 1 — Harness + corpus:** done. `fuzz/main.odin` reads one testcase file
  and calls `parser.parse`. Seed corpus is generated by
  `fuzz/corpus/gen_corpus.py` (the corpus dir is gitignored; the dictionary
  `fuzz/sql.dict` is committed alongside).
- **Phase 2 — ASan:** done. `-sanitize:address` build; all seeds pass. This phase
  already found and fixed a real bug: **stack overflow on deeply nested
  subqueries** (~5000 levels) — fixed with `MAX_PARSE_NESTING = 512` in
  `parse_select` + regression test `test_parse_deep_nesting_guard`.
- **Phase 3 — Black-box AFL++:** done (pipeline verified with a deliberate crash
  hook; now superseded by Phase 4).
- **Phase 4 — Coverage instrumentation:** done. `odin build -build-mode:llvm-ir`
  emits per-package LLVM IR **including the Odin runtime**; `afl-clang-fast`
  compiles it with the AFL++ LLVM pass and links `fuzz/fuzz_target_cov`. Verified
  via `afl-showmap` (non-empty map) and a live campaign: **~2400 exec/sec**
  (vs 333 dumb-mode), corpus 42→337 paths in 25 s, forkserver active.

Two targets now exist:

| Binary | Build | Use |
|---|---|---|
| `fuzz/fuzz_target` | `fuzz/scripts/build.sh` (ASan) | Regression gate (`fuzz-test`), crash confirmation (`run-one.sh`) |
| `fuzz/fuzz_target_cov` | `fuzz/scripts/build-cov.sh` (AFL++ instrumented, no ASan) | AFL++ campaigns (`run-afl.sh`) — fast, coverage-guided |

## Commands

```bash
# Regenerate the seed corpus (gitignored) — run from repo root
python3 fuzz/corpus/gen_corpus.py

# Build the ASan fuzz target (triage/regression)
make fuzz-build            # or fuzz/scripts/build.sh

# Build the coverage-instrumented target (campaigns)
make fuzz-cov-build        # or fuzz/scripts/build-cov.sh

# Run every seed under ASan (regression gate)
make fuzz-test

# Launch a coverage-guided campaign (interactive; Ctrl-C to stop)
make fuzz-run

# Headless 5-minute campaign
AFL_NO_UI=1 bash fuzz/scripts/run-afl.sh -V 300

# Parallel campaign (1 master + N-1 secondaries; N <= cores-1)
bash fuzz/scripts/run-afl-parallel.sh 4
# or with a time bound:
AFL_NO_UI=1 bash fuzz/scripts/run-afl-parallel.sh 4 -V 3600

# Reproduce a single testcase under ASan
fuzz/scripts/run-one.sh fuzz/afl-output/crashes/id:000000,*
```

AFL++ output goes to `fuzz/afl-output/` (gitignored; set `AFL_OUT` to override).
Crashes land in `fuzz/afl-output/crashes/` (each is a reproducer), hangs in
`fuzz/afl-output/hangs/`. Minimize with `afl-tmin` before filing a regression.

Note: in dumb-mode black-box runs, ASan can produce non-reproducible `SIGILL`
"crashes" (fork artifacts) — always confirm with `run-one.sh` before treating a
finding as real. The coverage build avoids this entirely.

## Findings so far (all fixed + regression-tested)

| # | How found | Bug | Fix |
|---|---|---|---|
| 1 | ASan corpus sweep (Phase 2) | Stack overflow on deeply nested subqueries (~5000 levels) | `MAX_PARSE_NESTING = 512` in `parse_select` |
| 2 | Coverage fuzz (≤1 s) | `tokenizer.odin:66` — 11-char identifier indexed a 10-char keyword (`keyword_bucket_offsets` ended at 58, not 59) → OOB | corrected offsets + length-equality guard in `match_keyword` |
| 3 | Coverage fuzz | `parse_ddl.odin` FK error-cleanup freed FK strings via `context.allocator` instead of the passed allocator → bad free | pass `allocator` to the FK `delete`s |

## Toolchain

See `fuzz/toolchain-version.txt` (recorded at setup). Notably:

- Odin: nightly (supports `-sanitize:address`, `-sanitize:memory`,
  `-build-mode:llvm-ir`).
- AFL++ 5.00c (`afl-fuzz`, `afl-clang-fast`, `afl-tmin`).
- Clang/LLVM 22.1.8.

Dev-workstation env flags used by `run-afl.sh`: `AFL_SKIP_CPUFREQ=1` (CPU
governor check) and `AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1` (system
`core_pattern` pipes core dumps to an external utility).

## Notes / decisions

- **Target choice:** parser-only first (fast, deterministic, no I/O). A second,
  higher-value target fuzzing the full `db.execute`/`db.query` stack (SQL →
  executor → storage) can be added later; it needs a scratch temp db per exec.
- **`statement_free` is `@(private)`** — the harness deliberately doesn't free
  the AST (one process per input, `temp_allocator` released at exit). A public
  free path would require polluting production code, which the guide advises
  against.
- **Deep nesting** is capped at `MAX_PARSE_NESTING` (512); the over-limit seed
  `deep_subquery_over_guard` in the corpus exercises the guard's clean-error path.
- AFL++ refuses to start if an initial corpus seed crashes the target (broken
  target policy). A crash found only by *mutation* (not in the corpus) is the
  signal that matters; the Phase 3 verification used a `CRASH;` proximate seed
  so a havoc mutation deleting the `;` produced the crashing `CRASH`.

## Regression policy

Every real crash found by fuzzing should be: minimized with `afl-tmin`,
confirmed reproducible, fixed, and committed as a regression test in
`tests/` (see `test_parse_deep_nesting_guard`). Do not commit `fuzz/afl-output/`
or generated corpora.
